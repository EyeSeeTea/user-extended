# Project context — User Extended App

This file is the project OVERVIEW and CONVENTIONS, written for the people who work on the project; AI agents read it too, as the source of the project's facts. How the AI protocol applies to the project lives in [`.est_ai/project.md`](./.est_ai/project.md). It is distinct from the behavioral capability specs under `openspec/specs/`. For setup/usage details see [`README.md`](./README.md).

## What it is

`user-extended-app` is a DHIS2 web app that extends user management: a paginated, filterable users list with bulk actions (edit, replicate, copy-in, enable/disable, passwords, import/export CSV/JSON), user groups and roles views, and app settings stored in the DHIS2 dataStore (default) or as constants.

## Tech stack

-   **Language**: TypeScript 4.9 (`typescript` in `package.json`); legacy JavaScript/JSX under `src/legacy/`
-   **Framework(s)**: React 17, `@dhis2/ui` 7, `@eyeseetea/d2-ui-components`, Material UI 4 (and `material-ui` 0.x in legacy code)
-   **External APIs / clients**: `@eyeseetea/d2-api` (DHIS2 Web API); legacy code also uses `d2`
-   **Tests**: Vitest 3 + Testing Library (`jsdom`, files `**/*.spec.{ts,tsx}`, setup `src/tests/setup.js`); Cypress 8 for E2E (`cypress/`)
-   **Build**: Vite 6 (`vite.config.ts`), `d2-manifest`
-   **Lint/format**: ESLint 8 (`.eslintrc.js`), Prettier 2
-   **Runtime**: Node `v22.22.0` (`.nvmrc`, `nvm use`), Yarn 4 via Corepack (`packageManager: yarn@4.12.0`)

## First-time setup (each developer)

After cloning, every developer runs these once — none of it is committed:

1. `nvm use` and `yarn install` (Corepack provides Yarn 4; see README → *Setup*).
2. Copy `.env` to `.env.local` and set `VITE_DHIS2_BASE_URL` and `VITE_DHIS2_AUTH` for your instance.
3. **Local Claude Code settings**: `cp .claude/settings.local.json.template .claude/settings.local.json`
4. **References** for the AI agents: clone or symlink the reference declared in [`.est_ai/project.md`](./.est_ai/project.md) into `.est_ai/reference/` as described in [`.est_ai/reference/README.md`](./.est_ai/reference/README.md). Without it, the agents work from the rules alone and the reviews report "no references available".

## Architecture

Clean Architecture for TypeScript code; dependencies point inward to the domain.

```
src/
  domain/
    entities/       Domain models, plus the project's own Future and Either
    repositories/   Repository interfaces only
    usecases/       Application logic; depend on repository interfaces
  data/
    repositories/   Implementations (*D2Repository, *D2ApiRepository, *D2ConstantRepository)
    entities/, models/, clients/, utils.ts
  webapp/           React UI: pages/, components/, contexts/, hooks/
  legacy/           Old JS/JSX UI (material-ui 0.x, d2); not extended
  CompositionRoot.ts  Wires repositories into use cases (created once in App.tsx)
  locales/          Generated by `yarn localize`; not versioned
```

A typical flow: a page or hook gets `compositionRoot` from `useAppContext()`, runs a use case, and the use case works through repository interfaces. The settings repository is chosen in `getCompositionRoot` by storage type (`AppSettingsD2Repository` for dataStore, `AppSettingsD2ConstantRepository` for constants). App settings are loaded once by `AppSettingsProvider` and read in the UI with `useAppSettingsContext()`.

## Code conventions

Project rules checked in reviews live in [`.est_ai/rules/project/`](./.est_ai/rules/project/README.md).

-   New code goes in the correct layer, in TypeScript, under `src/domain`, `src/data` or `src/webapp`.
-   Async code in `domain/` and `data/` returns the project's `FutureData` (`src/domain/entities/Future.ts`).
-   User-facing strings go through `i18n` (`@dhis2/d2-i18n`); `yarn update-po` updates `i18n/*.po`.

## Verification

Before considering a change done, run `yarn check` (typecheck, lint and tests).

## Testing strategy

-   Unit tests (`*.spec.ts`) next to the code in `__tests__/` folders, e.g. `src/domain/usecases/__tests__/`, `src/data/repositories/__tests__/`.
-   Use in-memory or mocked repositories (`ts-mockito` is available) to exercise use cases without hitting DHIS2.
-   Add or adjust tests whenever behavior changes.
-   E2E with Cypress against a real instance (`cypress/`), not run in normal development.

## Git workflow

-   Format (`yarn prettify`) before committing; the `pre-push` hook runs prettify, lint, `update-po` and tests.
-   Branch from `development` (unless the work depends on an unmerged branch); merge back to the same branch you started from.
-   Branch naming: `feature/<name>-<clickup-id>`, `fix/<name>-<clickup-id>`, `refactor/<name>`.
-   Commits follow [Conventional Commits](https://www.conventionalcommits.org/).
